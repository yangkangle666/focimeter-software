# LM700 / Hartmann 多光斑迁移说明

## 资料定位

本阶段阅读了老师资料目录中的 `README.md`、`2026-07-25_逆向-LM700-MATLAB移植-report.md`、`lm700_detect_spots.m`、`lm700_core.m`、`lm700_hartmann_dataflow.m` 与 `lm700_hartmann_analysis.m`。其中 MATLAB 文件是研究原型和算法线索，APK/符号提示是逆向证据；它们都不是已经恢复的 LM700 生产源码。尤其在 `HTM_dataTable`、`lm.dat`、真实标定表和实拍验证结果缺失时，不能宣称与 LM700 实机等价。

## 检测流程对应关系

| 老师资料中的 `lm700_detect_spots.m` 思路 | M2 C++ 实现 | 本阶段解释 |
| --- | --- | --- |
| 将灰度/RGB 输入转为数值图并处理非法值 | `ImageProcessor` 读取图片、转灰度并统一为 8-bit 工作图 | C++ 文件读取失败和位深转换异常走结构化错误；离线图片不会携带 MATLAB 的 NaN/Inf 像素矩阵语义 |
| 从图像四周估计背景 | `MultispotDetector::borderMean` | 实验路径在局部背景增强后估计边缘残差背景 |
| 由背景、亮像素均值和最小阈值推导阈值 | `multispot_background_factor`、`multispot_min_threshold`、亮像素均值和高分位数组合 | 对应“场景自适应阈值”思想，不逐行照搬 MATLAB 的常数 |
| 前景掩膜与 8 邻域连通域 | OpenCV `threshold`、3x3 开运算、`connectedComponentsWithStats` | 保留连通域方案，清理小噪声 |
| 面积/边缘过滤 | 内部 `multispot_min_area_pixels`、`multispot_max_area_ratio`、`multispot_border_margin_pixels` | 仅为合成数据的软件默认值，未写入统一配置 |
| 强度加权质心 | 对每个连通域按阈值以上的残差信号计算一阶矩 | 输出亚像素 `x`、`y`，单位为整图 pixel |
| 面积、积分强度、背景、阈值和数量诊断 | `SpotObservation`、`ImageDiagnostics` 与实验 JSON 的 `quality` | 便于 M2 诊断与未来 M3/M4 对接 |
| 行优先排序 | `y` 后 `x` 排序，生成 `detection_id` | 仅稳定输出顺序，不声明跨图物理身份 |
| 超过最大点数时按强度截断 | M2 直接返回安全失败 | 这是刻意差异：在正式阵列合同未定义前，静默丢点风险高于报错 |
| 网格局部极大值与最小点间距 | 当前未实现 | 连通域路径适合本阶段合成验证；真实碎裂、多峰和紧密阵列到位后必须与局部极大值方案对比 |

除上表之外，M2 复用了已有的输入校验、输出目录锁、成对结果发布、错误 JSON、可选中间图和 CTest 框架。多光斑路径通过 `--experimental-multispot` 显式启用；默认仍是 PR #4 的五点兼容路径。

## M2 和 M3 的边界

在**实验多光斑模式**中，M2 当前负责“看见哪些点以及每个点看起来是否可用”，不负责“两个图里的哪个点是同一条光线”。默认五点兼容模式仍由 M2 的 `SpotMatcher` 完成现有五点跨图配对。因此，多光斑边界是：

- M2 不产生正式跨图 `spot_id`，只产生图内 `detection_id`。
- M2 不计算参考图到测量图的位移、拟合波前、曲率、S/C/A 或显示量化步长。
- `lm700_hartmann_analysis.m`、`lm700_curvature_to_sca.m` 和 `lm700_quantize_step.m` 中的后续分析属于 M3/显示层理解材料，未迁移到 M2。
- 后续若要做多光斑物理配对，必须先批准匹配所有者、拓扑规则、缺失/伪点策略、匹配置信度和正式 JSON schema。

## 当前已验证与未验证内容

### 已完成的软件验证

- 可重复生成的 25 点与 94 点 PNG 阵列，以及平移、局部形变、亮度、背景梯度、噪声、低对比度和多类失败样例。
- 连通域检测、整图像素质心、质量字段、实验 JSON、失败 JSON、命令行入口和五点回归测试。
- 16 位容器不再固定假设完整 16 位有效范围；实验模式要求显式白电平，并已覆盖 12 位数据装在 16 位容器中的软件测试。
- 94 点只是合成压力样例，不是已确认的 LM700 孔数或光路参数。

### 仍被真实资料阻塞

1. 实际相机图像、位深、曝光范围、坏点和噪声特性。
2. 实际 Hartmann 孔径数量、间距、ROI、相机放大率和坐标标定。
3. `HTM_dataTable`、`lm.dat` 与真实标定表的含义和可用版本。
4. 标定图/测量图的真实点阵对应关系，以及缺失、遮挡、饱和时的业务规则。
5. 标准镜片上的识别率、匹配正确率和 S/C/A 计量误差。

因此，所有本阶段结果都只能写作 `software_verified` / `software_only`，且 `metrology_validated=false`；`data_source=real` 只表示输入来源，不代表计量验证。

## 真实资料到位后的路线

1. 先保存原始成对图与采集元数据，确认图像坐标、位深、背景图和光斑数量定义。
2. 用不参与调参的保留样本验证检测数量、质心误差、饱和/粘连/边缘处理和质量阈值。
3. 与负责人确定多光斑正式接口，再由 M2/M3 实现并验证跨图匹配与位移场。
4. 用标准镜片独立验证 M3 的波前与 S/C/A，才讨论 `metrology_validated`。

在此之前，不能通过填写看似合理的相机、焦距、像元尺寸或阵列间距常数来替代真实标定。
