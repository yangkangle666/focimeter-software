# 焦度计项目四大板块开发注意事项（AI 必读版）

> 使用方式：每个小组让 AI 开始干活前，先把本文件中对应板块发给 AI。  
> 本文件必须配合《团队统一开发规范_AI必读版.md》使用。  
> 目标：四个板块彼此独立开发，互不影响进度，最后通过统一接口合并成本地系统。

---

## 0. 四个板块总览

| 板块 | 名称 | 输入 | 输出 | 主要价值 |
|---|---|---|---|---|
| M1 | 输入与配置模块 | 图片路径、配置文件、样本数据 | 标准任务输入包 | 稳定地给系统喂数据 |
| M2 | 图像识别模块 | 标定图/测量图、图像处理参数 | 光斑坐标、质心、识别质量 | 把图片变成可计算坐标 |
| M3 | 标定与计算模块 | 标定光斑、测量光斑、光学参数 | S/C/A、质量判断 | 把坐标变化变成镜片参数 |
| M4 | 本地系统与展示模块 | 各模块输出或 mock 数据 | 可操作系统、日志、报告 | 把模块串成完整本地系统 |

每个板块都必须：

- 独立运行；
- 独立测试；
- 可用 mock 数据；
- 提供标准输入输出；
- 不依赖其他模块内部实现。

---

# M1 输入与配置模块

## 1. 模块定位

M1 是整个系统的数据入口。

它不负责识别光斑，也不负责计算度数，只负责：

- 管理标定图；
- 管理测量图；
- 管理配置参数；
- 管理样本路径；
- 输出标准任务输入包。

一句话：

```text
M1 负责把“散乱的图片和参数”整理成后续模块都能读懂的标准输入。
```

---

## 2. M1 必须实现的功能

第一阶段至少实现：

1. 读取配置文件；
2. 检查标定图路径是否存在；
3. 检查测量图路径是否存在；
4. 检查必要参数是否存在；
5. 输出标准 `input_package.json`；
6. 读取失败时输出统一错误；
7. 保存运行日志。

可选增强：

- 批量读取样本；
- 自动匹配标定图和测量图；
- 参数合法性检查；
- 简单图像预览；
- 相机接口预留字段。

---

## 3. M1 输入

M1 可以接收：

```text
config/default_config.json
图片目录
任务编号
运行模式
```

示例输入：

```json
{
  "task_id": "sample_001",
  "calibration_image": "data/samples/calibration/calib_001.png",
  "measurement_image": "data/samples/measurement/meas_001.png",
  "config_path": "config/default_config.json",
  "run_mode": "local_image"
}
```

---

## 4. M1 输出

M1 输出标准输入包，供 M2/M3/M4 使用。

示例：

```json
{
  "status": "ok",
  "task_id": "sample_001",
  "images": {
    "calibration": "data/samples/calibration/calib_001.png",
    "measurement": "data/samples/measurement/meas_001.png"
  },
  "config": {
    "camera": {
      "pixel_size_um": 4.0
    },
    "image_processing": {
      "roi_width_ratio": 0.9,
      "roi_height_ratio": 0.9
    }
  },
  "error": null
}
```

---

## 5. M1 与其他模块的联系

| 对接模块 | M1 提供什么 | 对方怎么用 |
|---|---|---|
| M2 图像识别 | 标定图路径、测量图路径、图像处理参数 | M2 读取图片并识别光斑 |
| M3 标定计算 | 相机像元尺寸、光路参数、计算参数 | M3 做单位换算和度数计算 |
| M4 本地系统 | 任务编号、配置、图片状态 | M4 展示任务、日志和错误 |

M1 不应该调用 M2/M3 内部函数。M1 只提供数据。

---

## 6. M1 特别注意

- 不允许硬编码个人路径；
- 不允许把不存在的文件当作正常输入；
- 不允许每组自己定义配置字段；
- 参数必须带单位；
- 缺失参数要明确报错；
- 配置中不知道的值用 `null`，不要乱填；
- 输出必须是标准 JSON；
- 本地路径最好使用相对路径。

---

## 7. M1 给 AI 的提示词

```text
你负责焦度计项目的 M1 输入与配置模块。
请遵守《团队统一开发规范_AI必读版.md》。
本模块只负责读取图片路径、配置文件和样本信息，不负责图像识别和度数计算。
请实现一个可本地独立运行的模块：
输入为任务 JSON 或配置路径；
输出为标准 input_package.json；
错误按统一 error 格式返回；
不要硬编码绝对路径；
请同时给出输入样例、输出样例和运行说明。
```

# M2 图像识别模块

## 1. 模块定位

M2 是把图片变成坐标的模块。

它不负责管理配置，也不负责计算镜片度数，只负责：

- 读取标定图/测量图；
- 图像预处理；
- 找到光斑；
- 计算质心；
- 输出光斑坐标和识别质量。

一句话：

```text
M2 负责把“光斑图片”变成“标准光斑坐标”。
```

---

## 2. M2 必须实现的功能

第一阶段至少实现：

1. 读取一张图片；
2. ROI 提取；
3. 灰度化；
4. 去噪；
5. 光斑增强；
6. 二值化；
7. 连通域筛选；
8. 质心计算；
9. 输出标准 spots JSON；
10. 保存中间图；
11. 识别失败时输出错误。

可选增强：

- 自动曝光质量判断；
- 光斑排序稳定性优化；
- 置信度评分；
- 支持批量图片；
- 支持不同光斑数量。

---

## 3. M2 输入

M2 输入来自 M1，或者第一阶段使用 mock 输入。

示例：

```json
{
  "task_id": "sample_001",
  "image_type": "calibration",
  "image_path": "data/samples/calibration/calib_001.png",
  "config": {
    "roi_width_ratio": 0.9,
    "roi_height_ratio": 0.9,
    "median_kernel": 3,
    "tophat_kernel": 30,
    "expected_spot_count": 5
  }
}
```

---

## 4. M2 输出

示例：

```json
{
  "task_id": "sample_001",
  "status": "ok",
  "image_type": "calibration",
  "coordinate_type": "image_pixel",
  "spots": [
    {
      "spot_id": 0,
      "role": "center",
      "x": 512.34,
      "y": 384.21,
      "confidence": 0.96
    }
  ],
  "quality": {
    "expected_count": 5,
    "detected_count": 5,
    "is_usable": true
  },
  "intermediate_images": [
    "outputs/images/sample_001_binary.png",
    "outputs/images/sample_001_spots.png"
  ],
  "error": null
}
```

---

## 5. M2 与其他模块的联系

| 对接模块 | M2 接收什么 | M2 输出什么 |
|---|---|---|
| M1 输入配置 | 图片路径、参数 | 光斑坐标 |
| M3 标定计算 | 不直接接收 M3 内容 | 标定图坐标、测量图坐标 |
| M4 本地系统 | 接收任务调度 | 中间图、识别状态、错误原因 |

M2 的核心输出是 `spots`，其他内容都是辅助。

---

## 6. M2 特别注意

- 坐标必须说明是图像像素坐标；
- 不要只在控制台打印坐标，必须输出 JSON；
- 标定图和测量图都要用同一套输出格式；
- 找不到 5 个点时不能直接崩溃；
- 光斑排序要稳定，尤其是中心点和方向点；
- 中间图要保存，方便后续查 bug；
- 置信度低时要给 warning；
- 不要在 M2 内部计算 S/C/A。

---

## 7. M2 常见风险

| 风险 | 后果 | 处理 |
|---|---|---|
| 光斑数量识别错误 | 后续计算无法进行 | 返回 `SPOT_COUNT_MISMATCH` |
| 中心点选错 | 坐标系错误 | 增加排序和角色判断 |
| 曝光过强/过弱 | 质心不准 | 增加质量判断 |
| 噪声被当作光斑 | 输出假坐标 | 加面积、亮度、形状筛选 |
| 输出坐标没单位 | M3 误算 | 固定 `coordinate_type=image_pixel` |

---

## 8. M2 给 AI 的提示词

```text
你负责焦度计项目的 M2 图像识别模块。
请遵守《团队统一开发规范_AI必读版.md》。
本模块只负责从标定图或测量图中识别光斑并输出质心坐标。
不要计算镜片度数，不要管理系统界面。
请实现可独立运行版本，输入为图片路径和处理参数，输出为标准 spots JSON。
识别失败时按统一 error 格式返回。
请保存中间图，并给出运行说明、输入样例、输出样例。
```

# M3 标定与计算模块

## 1. 模块定位

M3 是把坐标变成镜片参数的模块。

它不负责读取原始图片，也不负责界面展示，只负责：

- 根据标定图光斑建立坐标系；
- 将测量图光斑转到统一坐标系；
- 计算光斑位移；
- 判断镜片类型；
- 计算 S/C/A；
- 输出结果质量。

一句话：

```text
M3 负责把“光斑坐标变化”变成“镜片参数 S/C/A”。
```

---

## 2. M3 必须实现的功能

第一阶段至少实现：

1. 读取标定图 spots JSON；
2. 读取测量图 spots JSON；
3. 检查光斑数量和角色；
4. 建立标定坐标系；
5. 坐标转换；
6. 计算光斑位移；
7. 初步判断球镜/柱镜；
8. 输出 S/C/A；
9. 输出质量判断；
10. 错误时输出统一 error。

可选增强：

- 多点拟合；
- 误差估计；
- 公式参数校准；
- 标准镜片误差表；
- 结果置信度模型。

---

## 3. M3 输入

M3 输入来自 M2，第一阶段可以用 mock 坐标。

示例：

```json
{
  "task_id": "sample_001",
  "calibration_spots": "outputs/results/spots_calib_001.json",
  "measurement_spots": "outputs/results/spots_meas_001.json",
  "config": {
    "pixel_size_um": 4.0,
    "distance_m": 0.03,
    "pixel_threshold": 1.0,
    "angle_unit": "degree"
  }
}
```

---

## 4. M3 输出

示例：

```json
{
  "task_id": "sample_001",
  "status": "ok",
  "lens_type": "spherical",
  "result": {
    "S": -2.50,
    "C": 0.00,
    "A": null,
    "unit": "D"
  },
  "quality": {
    "is_usable": true,
    "confidence": 0.91,
    "warnings": []
  },
  "intermediate": {
    "coordinate_system_valid": true,
    "coordinate_type": "calibration_pixel",
    "shift_unit": "pixel"
  },
  "error": null
}
```

---

## 5. M3 与其他模块的联系

| 对接模块 | M3 接收什么 | M3 输出什么 |
|---|---|---|
| M2 图像识别 | 标定图光斑坐标、测量图光斑坐标 | 不回传内部计算 |
| M1 输入配置 | 像元尺寸、光路距离、阈值 | 不修改配置 |
| M4 本地系统 | 接收任务调用 | S/C/A、质量状态、错误原因 |

M3 不应该读取原始图片。如果需要调试，可以使用 M2 输出的中间图，但不能依赖它。

---

## 6. M3 特别注意

- 单位必须写清楚；
- 坐标系必须写清楚；
- 角度统一 degree；
- 不能直接照搬论文参数；
- 不确定的硬件参数必须标注 `TODO_CONFIRM`；
- 计算结果必须带质量判断；
- 公式变动必须记录原因；
- 不能让错误坐标继续参与计算。

---

## 7. M3 常见风险

| 风险 | 后果 | 处理 |
|---|---|---|
| 图像坐标和测量坐标混用 | 结果方向错误 | 明确 `coordinate_type` |
| 像素和物理长度混用 | 度数错误 | 字段名体现单位 |
| 角度弧度混用 | 轴位错误 | 统一 degree |
| 中心点错误 | 整个坐标系错误 | 检查 spot role |
| 公式依据不清 | 答辩和验证风险 | 写计算说明 |

---

## 8. M3 给 AI 的提示词

```text
你负责焦度计项目的 M3 标定与计算模块。
请遵守《团队统一开发规范_AI必读版.md》。
本模块只接收光斑坐标和配置参数，不直接处理原始图片。
请实现可独立运行版本：
输入为 calibration_spots、measurement_spots 和 config；
输出为标准 S/C/A result JSON；
必须写清坐标系、单位和错误处理。
不确定的公式或硬件参数请标注 TODO_CONFIRM，不要编造。
```

# M4 本地系统与展示模块

## 1. 模块定位

M4 是把系统串起来的模块。

它不负责重新写图像算法，也不负责重新推公式，只负责：

- 本地系统主流程；
- 调用其他模块；
- 展示结果；
- 保存日志；
- 导出报告；
- 显示异常提示；
- 为后续软件化做准备。

一句话：

```text
M4 负责把 M1/M2/M3 的能力串成一个用户能操作的本地系统。
```

---

## 2. M4 必须实现的功能

第一阶段至少实现：

1. 本地系统主界面或主程序；
2. 读取任务输入；
3. 使用 mock 数据展示完整流程；
4. 显示 S/C/A；
5. 显示质量状态；
6. 保存日志；
7. 导出结果；
8. 显示错误信息。

可选增强：

- 简单图形界面；
- 图片预览；
- 中间图展示；
- 批量任务；
- 报告导出；
- 模块状态面板；
- 后续相机接口预留。

---

## 3. M4 输入

M4 可以输入：

```text
M1 标准输入包
M2 光斑识别结果
M3 S/C/A 计算结果
mock_result.json
```

第一阶段优先使用 mock 数据，不等待其他模块。

示例：

```json
{
  "task_id": "sample_001",
  "status": "ok",
  "result": {
    "S": -2.50,
    "C": 0.00,
    "A": null,
    "unit": "D"
  },
  "quality": {
    "is_usable": true,
    "confidence": 0.91
  }
}
```

---

## 4. M4 输出

M4 输出包括：

```text
结果展示
运行日志
结果 JSON
CSV 或报告
错误提示
过程图引用
```

示例结果文件：

```json
{
  "task_id": "sample_001",
  "display_status": "success",
  "result_text": "S=-2.50D, C=0.00D, A=N/A",
  "result_file": "outputs/results/result_001.json",
  "log_file": "outputs/logs/log_system_001.json",
  "report_file": "outputs/reports/report_001.html"
}
```

---

## 5. M4 与其他模块的联系

| 对接模块 | M4 接收什么 | M4 做什么 |
|---|---|---|
| M1 输入配置 | 任务输入包 | 显示任务信息，传给后续模块 |
| M2 图像识别 | 光斑坐标、中间图、识别质量 | 展示识别状态和过程图 |
| M3 标定计算 | S/C/A、质量状态、错误 | 展示结果并导出报告 |

M4 是合并阶段的总控位置，但不能私自修改其他模块输出格式。

---

## 6. M4 特别注意

- 第一阶段不要等其他模块，先用 mock 数据；
- 不要在 M4 里重写 M2/M3 的核心逻辑；
- 重点是流程、展示、日志、导出；
- 错误提示要让人看得懂；
- 结果字段要和 M3 保持一致；
- 后续软件化时，M4 是最容易扩展成界面的模块；
- 合并时优先保证主流程跑通，不要先追求界面好看。

---

## 7. M4 常见风险

| 风险 | 后果 | 处理 |
|---|---|---|
| 等其他模块完成才开始 | 进度被拖慢 | 用 mock 数据先做 |
| 把算法写进展示层 | 后续难合并 | 只调用模块接口 |
| 错误提示太少 | 难以调试 | 保存日志和错误原因 |
| 输出格式随意 | 报告难生成 | 使用统一 result JSON |
| 界面先行过度 | 核心流程没跑通 | 先做主流程，后做美化 |

---

本模块负责主流程、展示、日志、导出和异常提示。
第一阶段请使用 mock 数据先做出可演示的本地系统，不等待其他模块完成。
不要重新实现图像识别和 S/C/A 计算，只通过统一接口调用或读取结果。

# 四组协作注意事项

## 1. 每组两人怎么合作

建议每组两人固定分工：

| 角色 | 任务 |
|---|---|
| 主开发 | 用 AI 生成代码、整理功能、推进模块 |
| 主审查 | 检查接口、跑样本、找 bug、确认输出格式 |

两人不能都只让 AI 写代码，必须有人负责验证。

---

## 2. 每组每天要同步什么

每天同步时只说四件事：

```text
今天完成了什么？
当前输入输出是否符合规范？
有没有影响其他组的接口变化？
卡点是什么？
```

不要开会时讨论太多细节，细节写到模块日志和问题清单里。

---

## 3. 每组交付物模板

每组交付时至少包含：

```text
module_name/
  README.md
  run 方法
  输入样例
  输出样例
  错误样例
  当前版本
  当前限制
  TODO_CONFIRM 列表
```

---

## 4. 合并前每组必须准备

- [ ] 模块可独立运行；
- [ ] mock 数据可运行；
- [ ] 输出 JSON 符合规范；
- [ ] 错误 JSON 符合规范；
- [ ] 日志能保存；
- [ ] 路径不写死；
- [ ] 单位写清楚；
- [ ] 坐标系写清楚；
- [ ] README 写清楚；
- [ ] 知道自己和其他模块的接口关系。
